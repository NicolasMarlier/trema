Déployer Trema depuis le dossier du repo trema

La tâche n'a pas de description. Voici comment je la comprends : depuis un checkout du repo trema (le clone principal ou un worktree Usine), une seule commande déploie Trema lui-même sur le VM (UI trema.nicolasm.fr, scripts serveur, templates, hooks), avec le code de ce dossier. Aujourd'hui, ce n'est pas possible.

Constat

ProblèmeConséquence
load_env exige un trema.env dans le dossier courant.trema ui:install, server:setup et update échouent dans le repo trema (« trema.env not found »). Il faut se placer dans une app pour mettre à jour Trema.
trema_path utilise which trema.On déploie la copie installée dans le PATH, pas le code du dossier courant. Dans un worktree, ce qu'on déploie n'est donc pas ce qu'on vient de modifier.
trema deploy est appelée mais n'est pas définie.La commande « naturelle » ne fait rien et le code est mort.
update ne recopie le hook que dans l'app courante.Les autres apps gardent l'ancien hook.

Proposition

  • Nouvelle commande (nom : voir Q1) lancée depuis la racine du repo trema, également disponible via npm run deploy.
  • Code : celui du dossier où se trouve le script (bin/..), plus celui de which trema. On corrige trema_path pour toutes les commandes.
  • Cible : on lit ~/.trema_config (hostname / user). Pas besoin de trema.env. Si TREMA_HOSTNAME manque, on affiche un message clair qui renvoie vers trema config:edit --global.
  • Étapes (périmètre : Q2) : tests → templates → server:setup → build + installation de l'UI → hooks de toutes les apps → vérification HTTP de l'UI.
  • Non interactif si auth.json existe déjà, pour qu'Usine puisse l'exécuter à l'étape « Déploiement ». Sinon : demande du mot de passe si on a un TTY, échec explicite sinon.
  • On s'arrête à la première erreur et on affiche un récapitulatif ✅/❌ par étape. On garde une trace (commit déployé + date) dans ~/trema-ui/VERSION sur le VM, et l'UI peut l'afficher.

Hors périmètre

  • Déployer Trema par git push (Trema s'auto-hébergeant comme une app) : c'est possible plus tard, mais cela change le modèle (l'UI n'est pas un conteneur).
  • Le rollback automatique de l'UI (on pourra garder ~/trema-ui.prev si besoin, voir Q4).

Tests

Tests bash dans tests/ : résolution de trema_path depuis un worktree, config globale sans trema.env, erreur claire quand la config manque, ordre des étapes et arrêt à la première erreur (ssh/rsync simulés).
