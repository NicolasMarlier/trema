Usine · trema · T-4 · Spec (v2)

Une meilleure interface pour trema ui

Version 2 de la spec, qui intègre vos réponses. Le front livré en T-3 (ui/public/index.html) est un rendu brut. Il passe en React + Vite, au niveau du prototype de T-3, avec un thème sombre uniquement. Trois petits ajouts côté serveur : URL de l'app, message de commit et jauges du VM. Les secrets restent masqués côté serveur. Les appels lents (Docker) ont maintenant un traitement soigné.

Périmètre

  • Structure : une barre latérale (apps, statut, jauges du VM), un en-tête d'app (statut, lien vers l'URL publique, actions) et des onglets Vue d'ensemble · Logs · Env · Déploiements. L'ancre #/blog/logs garde la position au rechargement.
  • Chargements : squelettes au premier affichage. Ensuite, les données déjà connues restent affichées pendant le rafraîchissement. Chaque zone a son propre chargement et rien ne bloque la page entière. Les actions longues ont un bandeau de progression avec chrono.
  • Retours : les boutons sont verrouillés pendant une action, des toasts remplacent les alert(), et Arrêter / Redéployer demandent une confirmation.
  • Statut vivant : rafraîchissement automatique toutes les ~10 s, avec 4 états (en ligne, dégradée, arrêtée, inconnue) plus « en cours ».
  • Logs : suivi automatique, pause, filtre et couleurs pour les avertissements et les erreurs.
  • Env : valeurs masquées, « Voir » charge la valeur à la demande, ajout et suppression, et récapitulatif des changements (+ / ~ / −) avant de redéployer.
  • Déploiements : dates relatives, message de commit, durée lisible et pastilles de statut.
  • Écrans d'erreur et cas vides : Docker injoignable, app jamais déployée, conteneurs arrêtés.

Apps
Tout est cliquable. « Réseau lent » simule des délais réalistes (docker stats ≈ 2–3 s), et « Recharger » rejoue le premier affichage avec les squelettes. Essayez « Voir » sur une variable, puis modifiez-la et faites « Enregistrer & redéployer ». Le bandeau de progression dépend de la réponse à Q7.

Chargements — stratégie

Mesures sur le serveur actuel : /api/apps appelle docker ps (~0,5–1,5 s), /stats appelle docker ps puis docker stats --no-stream (~2–3 s), et PUT /env attend la fin de compose up --build (30 s à plusieurs minutes) dans une seule requête HTTP.

NiveauTraitement
Premier affichageLes squelettes ont la forme finale (liste, cartes, tableaux), donc pas de saut de mise en page. Chaque zone se remplit dès que sa propre requête répond.
RafraîchissementLes données en cache restent affichées pendant la mise à jour (stale-while-revalidate), avec un petit indicateur ↻. Un changement d'app ou d'onglet affiche tout de suite ce qui est déjà connu.
Actions courtes (restart / stop / start)Boutons verrouillés, pastille « en cours » sur l'app, chrono, puis toast et rafraîchissement ciblé.
Actions longues (redéploiement env)Bandeau de progression persistant, même si l'on change d'onglet ou d'app. Voir Q7 : job asynchrone avec sortie en direct, ou simple chrono.
ServeurVoir Q8 : un collecteur en tâche de fond interroge Docker toutes les ~5 s, et l'API répond instantanément depuis la mémoire.

Parcours « modifier l'env »

Le navigateur n'a jamais toutes les valeurs, donc il n'envoie que le diff. Le serveur l'applique avec mergeEnv, qui préserve les commentaires et l'ordre du fichier.

Approche technique

SujetProposition
Frontui/web/ : React + Vite + TypeScript. Le build produit ui/dist/, qui n'est pas commité. Le code est découpé en onglets, avec un petit hook de cache maison (useResource : données, chargement, rafraîchissement). Pas de dépendance d'UI : le CSS reprend les jetons Usine en version sombre.
Installtrema ui:install lance npm ci && vite build en local, puis envoie par rsync ui/server.mjs, ui/lib.mjs et ui/dist. Node devient donc nécessaire sur le poste pour l'installation. En prod, rien ne change : pas de node_modules.
API GET /api/apps : ajoute url (server_name de /etc/nginx/sites-enabled/<app>) et le nombre de conteneurs actifs / total.
GET /api/system : CPU, RAM et disque du VM (/proc, os, statfs).
GET /env : renvoie les clés seules (valeurs masquées). GET /env/:key : renvoie une valeur. PATCH /env : reçoit {set, unset} au lieu de la liste complète.
deploys.log : 5ᵉ colonne avec le message de commit, écrite par le hook post-receive. Les anciennes lignes restent lisibles.
Q7 = a : les actions renvoient 202 {job}, avec GET /api/jobs/:id/stream en SSE.
TestsFonctions pures testées avec node --test : formatage (dates relatives, durées, mémoire), diff d'env, classement des lignes de log, parsing deploys.log v2 / nginx / /proc. Côté front, la logique vit dans des modules TS sans React, testables de la même façon.
Hors périmètreThème clair, nouvelles actions (dumps DB, suppression d'app, console), plusieurs serveurs, graphes historisés, authentification (on garde le tunnel SSH).

Questions ouvertes

Job asynchrone : l'API répond tout de suite, la sortie de docker compose s'affiche en direct dans le bandeau, et le suivi survit à un rechargement
Garder une requête synchrone, avec seulement un bandeau et un chrono côté front

Reco : a. Une requête bloquée pendant plus d'une minute est fragile (timeouts, onglet rechargé) et n'explique rien en cas d'échec. Le streaming SSE existe déjà pour les logs.

Oui : un collecteur interroge docker ps / stats et le VM toutes les ~5 s, et l'API répond depuis la mémoire
Non : chaque requête appelle Docker, et le front gère l'attente

Reco : a. C'est le vrai remède à la lenteur : la page et les changements d'app deviennent instantanés, et Docker n'est plus sollicité à chaque onglet ouvert. Le coût est faible (~40 lignes).

Toutes : il faut cliquer « Voir » pour chaque valeur
Seulement les clés sensibles (*PASSWORD*, *SECRET*, *TOKEN*, *KEY*, DATABASE_URL…) ; les autres sont affichées en clair

Reco : b. Lire RAILS_ENV=production ne devrait pas demander un clic. La détection existe déjà dans isSecretKey. Le prototype suit votre choix.

Garder node:http sans dépendance (le serveur est petit, le déploiement reste un simple rsync)
Migrer vers Hono (stack préférée), avec node_modules installé sur le VM

Reco : a. La refonte porte sur le front. Hono imposerait un npm ci sur le VM pour un gain faible.
