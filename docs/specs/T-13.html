Déployer sur push GitHub (façon Vercel), avec sous-dossier racine

Aujourd'hui, une app Trema se déploie uniquement par git push trema main vers le dépôt nu de la VM. On propose deux ajouts : (1) brancher une app sur un dépôt GitHub et une branche, pour qu'un push sur GitHub la redéploie automatiquement ; (2) un dossier racine par app (ex. backend/ ou frontend/), pour qu'un monorepo alimente plusieurs apps Trema.

Proposition

① Source GitHub

Nouvel onglet « Source » dans l'UI. On y saisit le dépôt, la branche et le dossier racine. Trema fournit en retour :
  • l'URL du webhook https://trema.<host>/api/hooks/github/<app> et un secret à coller dans GitHub ;
  • pour un dépôt privé, une deploy key en lecture seule, générée par Trema (Q2).

② Dossier racine

Le hook cherche docker-compose.yml, .env.example et l'app Rails dans ce dossier, et lance docker compose depuis ce dossier. Le réglage vaut pour les deux modes : push GitHub et git push trema. Le nom du projet compose est forcé au nom de l'app (-p <app>). Sinon, deux apps dont le dossier s'appelle backend partageraient les mêmes conteneurs.
Principe : on ne crée pas un second pipeline. À la réception du webhook, le serveur de l'UI vérifie la signature HMAC, la branche et les fichiers modifiés. Il fait ensuite un git fetch depuis GitHub vers le dépôt nu existant, puis lance le même hook post-receive qu'un git push trema. L'historique, les logs et les règles de migration restent donc les mêmes.
