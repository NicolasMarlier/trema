Usine · trema · T-1 · Spec

Exécuter db:migrate à chaque déploiement (template Rails uniquement)

Contexte

Le hook hooks/post-receive déploie une app soit avec son propre docker-compose.yml (custom), soit avec le template Rails + Postgres (RoR_3_4_8_Puma.Dockerfile + ruby_on_rails_postgres.yml). Aujourd'hui, aucune migration n'est jouée : après un git push trema main contenant une migration, l'app démarre sur un schéma obsolète et il faut lancer trema console à la main.

Objectif : lors d'un déploiement d'une app utilisant le template Rails (CUSTOM_COMPOSE=0), jouer les migrations automatiquement avant que la nouvelle version ne reçoive du trafic. Les apps custom ne sont pas concernées.

Proposition (approche recommandée : C)

  1. Build l'image web (docker compose build).
  2. Démarrer la base seule et attendre qu'elle soit prête (healthcheck pg_isready ajouté au service db du template).
  3. Migrer dans un conteneur jetable : docker compose run --rm web bin/rails db:prepare (ou db:migrate, cf. Q1).
  4. Si la migration échoue → arrêt du déploiement, l'ancien conteneur web continue de servir ; le log d'erreur s'affiche dans la sortie du git push.
  5. Sinon → docker compose up --force-recreate -d comme aujourd'hui, puis nginx.

Le bloc ne s'exécute que si CUSTOM_COMPOSE=0. Pas de nouvelle variable de config requise.
