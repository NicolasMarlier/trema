Supprimer la config locale trema.env

Aujourd'hui, chaque projet a un trema.env (hôte, utilisateur, nom de l'app), créé par trema init et exigé par presque toutes les commandes via load_env, y compris les commandes globales (ui, ui:install, server:setup…). Or hôte et utilisateur sont déjà dans ~/.trema_config, et le nom de l'app est déjà dans le remote git trema (user@host:repos/<app>). Le fichier est donc redondant.

Proposition

  • Hôte + utilisateur : lus uniquement dans ~/.trema_config. S'ils manquent : erreur claire qui renvoie vers trema config:edit --global.
  • Nom de l'app : déduit du remote git trema du dossier courant (…:repos/<app>), surchargeable par --app <nom> (Q1).
  • Deux familles de commandes : les commandes globales n'ont plus besoin d'être lancées dans un projet ; seules les commandes d'app cherchent le nom de l'app.
  • trema init ne pose plus de questions et n'écrit plus de fichier : il prend l'hôte/utilisateur globaux, le nom du dossier comme nom d'app, puis crée repo, hook, vhost, certificat et remote comme aujourd'hui.
  • trema destroy ne supprime plus trema.env (il retire seulement le remote).
  • trema config : plus de notion locale (Q4). config:edit édite la config globale.
  • UI : le bloc « commandes à copier » (T-10) perd la ligne printf … > trema.env ; il reste git remote add + git push.
  • Docs : architecture.html, zones.svg, README, aide de la CLI.
  • Tests : bash (résolution du nom depuis le remote, --app, erreurs config/remote absents, commande globale hors projet) + test Node de localCommands.
