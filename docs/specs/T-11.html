Supprimer trema.env et trema init

Chaque projet a aujourd'hui un trema.env (hôte, utilisateur, nom de l'app). Ce fichier est créé par trema init, et presque toutes les commandes l'exigent. Il fait doublon : l'hôte et l'utilisateur sont déjà dans ~/.trema_config, et le nom de l'app est déjà dans le remote git trema. Depuis T-10, la création d'une app se fait dans l'UI, donc trema init ne sert plus non plus.

Décisions

Q1 · Nom de l'appIl est lu dans le remote git trema (…:repos/<app>). L'option --app <nom> permet de le forcer ou de lancer la commande hors du projet. reco
Q2 · Hôte / utilisateurIls viennent toujours de ~/.trema_config. Si l'hôte du remote est différent, la commande s'arrête avec une erreur explicite. Le multi-VM n'est plus supporté. reco
Q3 · Config globale absenteErreur claire qui renvoie vers trema config:edit --global. Cela vaut pour toutes les commandes, puisque init disparaît. reco
Q4 · config / config:editSans option, elles gèrent la config globale ; config affiche aussi l'app détectée, pour info. --global reste accepté comme alias. reco
Q5 · trema.env existantsSupprimés automatiquement. ≠ reco
Remarquetrema init est supprimé : on crée désormais l'app depuis l'UI (T-10).

Proposition

  • Config : une seule source, ~/.trema_config. load_env est remplacé par deux étapes :
    • la vérification de la config globale, faite pour toutes les commandes ;
    • la résolution de l'app (--app, sinon le remote trema), faite seulement pour les commandes d'app.
  • Commandes globales (ui*, server:setup, ssh) : elles marchent depuis n'importe quel dossier.
  • Commandes d'app (logs, console, env, migrate, destroy, update, load_pg_dump, archive_db, heroku_pg_dump) : il leur faut un nom d'app. Sans remote ni --app, l'erreur renvoie vers l'UI.
  • trema init supprimé, avec son code (init, add_nginx_config). La création se fait dans l'UI, qui fournit les commandes à copier (Q6 : ce que la CLI répond si on tape encore init).
  • Migration : si la CLI trouve un trema.env dans le dossier courant, elle le supprime et l'indique sur une ligne (Q7 : cas où son contenu diffère de la config globale).
  • trema destroy retire seulement le remote. Il ne touche plus à trema.env.
  • UI : le bloc « commandes à copier » perd la ligne printf … > trema.env (ui/lib.mjs). Les commentaires « équivalent de trema init » sont mis à jour.
  • Docs à mettre à jour : architecture.html, zones.svg, le README et l'aide de la CLI (usage et trema-config).
  • Tests :
    • bash : nom lu dans le remote, --app, config absente, remote absent, hôte différent, commande globale lancée hors projet, suppression de trema.env, réponse à init ;
    • Node : localCommands sans trema.env.
